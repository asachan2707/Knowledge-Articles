CSS offset-path — Motion Along Any Path

offset-path is a CSS property that moves elements along an arbitrary geometric path — an SVG curve, a circle, a polygon — using pure CSS. It replaces entire JavaScript animation rigs with a handful of declarative properties and runs on the compositor thread.

Source: YouTube — CSS Deep Dive Domain: CSS / Frontend Animation Published: 2024

Before offset-path, animating an element along a curved path meant calculating coordinates in JavaScript on every frame — a main-thread operation that janked on mobile and required libraries like GSAP or anime.js. The CSS Motion Path module changes that: define the path once, animate offset-distance from 0% to 100%, and the browser handles the rest entirely off-main-thread.

Core idea: offset-path defines where to move; offset-distance defines how far along. Animate the distance and you get path-following motion in pure CSS.

Story · The carousel dot problem

A designer hands you a spec: a loading indicator where three dots orbit in an ellipse, each spaced evenly, each rotating to stay tangent to the curve. In JavaScript, that's trigonometry per frame, three requestAnimationFrame loops, and careful cleanup to prevent memory leaks. With offset-path it's three elements, one SVG ellipse path, and animation-delay stagger. The GPU compositor handles the interpolation — silky smooth even on a budget Android phone.

The properties

The CSS Motion Path property set

Five properties form the full API:

  • offset-path — defines the path. Accepts:
    • path('M 0 0 C 100 0 200 100 200 200') — SVG path data string
    • circle(50px at 50% 50%) — CSS basic shape
    • ray(45deg closest-side) — a ray from the element's container
    • url(#svgPathId) — reference to an inline SVG <path> element
  • offset-distance — how far along the path (0% = start, 100% = end). This is the animatable value.
  • offset-rotate — how the element rotates as it moves. auto keeps it tangent to the path; auto 90deg adds a fixed offset; 0deg keeps it upright regardless of path direction.
  • offset-anchor — which point of the element sits on the path (default is the transform-origin, usually center).
  • offset-position — defines where the path starts in the coordinate space when no explicit start is encoded in the path data.
Concept 2

Path types in depth

SVG path string

The most flexible option. Any SVG path command works — lines (L), cubic beziers (C), arcs (A), and more. You can sketch the path in Figma, export the d attribute, and drop it straight into path('...'). No inline SVG element required.

CSS basic shapes

circle(), ellipse(), polygon(), and inset() work as paths. An element orbiting on a circle(80px) path needs zero SVG — the path is computed from the CSS alone.

SVG element reference

url(#myPath) references an inline <path> inside an <svg> in the document. This is ideal when the path is already part of the visual design (e.g. a decorative curve the element should follow).

ray()

The ray() function defines a straight line at a given angle from the element's containing block. Useful for starburst effects or elements shooting out from a central point.

Concept 3

Performance model

offset-distance is a composited property — the browser can animate it entirely on the GPU compositor thread without touching the main thread. This means:

  • No layout or paint recalculations during the animation.
  • No JavaScript execution per frame.
  • The animation continues smoothly even when the main thread is busy (parsing scripts, running event handlers, etc.).

The one caveat: if the element's size or shape changes during the animation (triggering layout), the compositor advantage is lost. Keep animated elements' dimensions fixed.

Concept 4

Browser support and fallbacks

As of 2024, offset-path has baseline support across all major engines (Chrome 79+, Firefox 72+, Safari 15.4+). The path() value is the most widely supported form; ray() and url() have slightly newer baselines.

For older browsers, wrap the animation in a @supports query and provide a simpler translate fallback: 

.dot {
  /* fallback: simple translate bounce */
  animation: bounce 1s ease-in-out infinite;
}

@supports (offset-path: path('M 0 0')) {
  .dot {
    animation: none;
    offset-path: path('M 0 0 A 80 80 0 1 1 0 -0.01');
    animation: orbit 2s linear infinite;
  }
}
JavaScript Example

Generating and animating a motion path programmatically

JavaScript Example 
/**
 * Dynamically assign an offset-path to elements and stagger them
 * along an SVG bezier curve — no animation library required.
 */

const SVG_PATH = 'M 0 200 C 50 0, 150 400, 200 200 S 350 0, 400 200';

/**
 * Animate a NodeList of elements along a shared SVG path, staggered.
 * @param {NodeListOf} elements
 * @param {object} opts
 */
function animateAlongPath(elements, { duration = 2000, staggerMs = 200 } = {}) {
  elements.forEach((el, i) => {
    // Apply motion path properties
    el.style.offsetPath = `path('${SVG_PATH}')`;
    el.style.offsetRotate = 'auto';

    // Use the Web Animations API to drive offset-distance
    el.animate(
      [{ offsetDistance: '0%' }, { offsetDistance: '100%' }],
      {
        duration,
        delay: i * staggerMs,
        iterations: Infinity,
        easing: 'linear',
        fill: 'none',
      }
    );
  });
}

// Usage
const dots = document.querySelectorAll('.orbit-dot');
animateAlongPath(dots, { duration: 3000, staggerMs: 400 });

/**
 * Reverse direction for every other element — useful for bidirectional orbits.
 */
function animateBidirectional(elements) {
  elements.forEach((el, i) => {
    const direction = i % 2 === 0 ? 'normal' : 'reverse';
    el.style.offsetPath = `circle(80px at 50% 50%)`;
    el.style.offsetRotate = 'auto';
    el.animate(
      [{ offsetDistance: '0%' }, { offsetDistance: '100%' }],
      { duration: 2500, iterations: Infinity, direction, easing: 'linear' }
    );
  });
}

/**
 * Smoothly update the path at runtime (e.g. in response to a resize or interaction).
 * Cancels old animations and re-applies with the new path geometry.
 */
function updatePath(elements, newPathD) {
  elements.forEach((el) => {
    el.getAnimations().forEach((anim) => anim.cancel());
    el.style.offsetPath = `path('${newPathD}')`;
    el.animate(
      [{ offsetDistance: '0%' }, { offsetDistance: '100%' }],
      { duration: 2000, iterations: Infinity, easing: 'ease-in-out' }
    );
  });
}
Practical checklist

Using offset-path well

  • Prefer path() with SVG path data for complex curves; use circle() / ellipse() for simple orbits.
  • Set offset-rotate: auto for elements that should face the direction of travel (arrows, cars, indicators).
  • Animate offset-distance not offset-path — the former is composited; the latter triggers layout.
  • Use @supports (offset-path: path('M 0 0')) to gate the fancy animation and provide a CSS fallback.
  • Keep animated elements at a fixed size — any layout-triggering change drops the compositor-thread advantage.
  • Use animation-delay staggering to space multiple elements along the same path without duplicating keyframe definitions.
  • Export paths from Figma or SVG editors; the d attribute value drops directly into path('...').
FAQ

Common questions

Can I use a path drawn in an external SVG file?

No — url(#id) only resolves inline SVG elements in the same document. For external paths, fetch the SVG, extract the d attribute, and pass it as a path() string value.

How do I make the element loop seamlessly?

Close the SVG path — end it at the same coordinate it started. A closed path with iterations: Infinity loops without a visible jump. For open paths, direction: alternate reverses playback on each iteration.

Can I combine offset-path with CSS transforms?

Yes. offset-path and transform compose: the element is positioned on the path first, then the transform is applied on top. This lets you add scale or rotation effects independently of the path motion.

Is this different from SVG animateMotion?

animateMotion is an SVG-only mechanism for moving SVG child elements along a path. CSS offset-path works on any HTML element — divs, images, custom elements — and integrates with the Web Animations API and CSS transitions, giving it far more flexibility.

Key Takeaway

offset-path collapses what used to be a JavaScript animation problem into a few CSS declarations. The key mental shift is thinking of an element's position not as x,y coordinates but as a distance along a named path. Once you internalize that model — path defines the geometry, offset-distance is the animated scalar — you can build orbital loaders, path-following icons, decorative scroll effects, and SVG-synchronized UI elements with zero runtime JavaScript and full compositor-thread performance.
