Jev: Teaching a Model to Return Numbers Instead of Text

Jev is a decision engine that returns confidence scores across predefined outcome categories in a single forward pass — no text generation, no parsing, no fragile regex. When your downstream code needs numbers not prose, Jev's architecture is the pattern to understand.

What Jev Is

Jev is a decision engine released by TypeSafe AI. Unlike standard LLMs, it cannot generate conversational text — it returns numeric confidence scores across defined outcome categories in a single forward pass.

Traditional LLMs answer questions by generating tokens sequentially:

"Based on the line items and vendor history, this invoice appears to be legitimate."

Jev returns numeric scores across predefined categories instead:

fraud
0.07
clean
0.88
review
0.05

LLM vs. Jev: When to Use Which

Standard LLM

  • Output: natural language paragraph
  • Parsing required: yes — fragile
  • Good for: explanations, summaries, generation
  • Branching: extract intent from text → complex
  • Cost: full generation overhead per call

Jev Decision Engine

  • Output: numeric probability scores
  • Parsing required: no — consume numbers directly
  • Good for: routing, gating, classification, scoring
  • Branching: threshold check in plain code
  • Cost: single forward pass — no generation
The key advantage: All questions are evaluated simultaneously in one pass. With an LLM you must chain prompts ("first classify, then explain"); with Jev all scores are computed atomically.

Architecture Pattern

State + Questions → Jev → Scores → Threshold Check → Code Branch Executes

The model never runs the branching logic. Regular code does, using the scores Jev returns as inputs. This is the key design principle.

// Simulated Jev-style decision engine interface
class JevDecisionEngine {
  constructor(categories) {
    this.categories = categories; // predefined outcome categories
  }

  // Returns confidence scores (sums to ~1.0)
  async score(context) {
    // In a real system, this sends to the Jev API
    // Here we simulate scoring for illustration
    return this._simulateScoring(context);
  }

  _simulateScoring(context) {
    // Simulate based on simple heuristics for demo
    const scores = {};
    let total = 0;

    this.categories.forEach(cat => {
      scores[cat] = Math.random();
      total += scores[cat];
    });

    // Normalize to sum to 1.0
    this.categories.forEach(cat => {
      scores[cat] = parseFloat((scores[cat] / total).toFixed(4));
    });

    return scores;
  }
}

// Usage: invoice fraud detection
const fraudDetector = new JevDecisionEngine(["fraud", "clean", "review"]);

async function classifyInvoice(invoice) {
  const context = {
    amount: invoice.amount,
    vendorHistory: invoice.vendorHistory,
    lineItemCount: invoice.lineItems.length,
    unusualTimings: invoice.submittedAt.getHours() < 6
  };

  const scores = await fraudDetector.score(context);

  // Branching logic lives entirely in regular code
  if (scores.fraud > 0.7)      return { action: "block",  reason: "high fraud confidence",  scores };
  if (scores.review > 0.3)     return { action: "review", reason: "manual review required", scores };
  if (scores.clean > 0.8)      return { action: "approve", reason: "high clean confidence", scores };
  return                               { action: "review", reason: "low confidence — escalate", scores };
}

// Test
classifyInvoice({
  amount: 47000,
  vendorHistory: "new_vendor",
  lineItems: [{ desc: "consulting", qty: 1 }],
  submittedAt: new Date("2026-09-15T03:15:00Z") // 3am submission
}).then(result => {
  console.log(`Action: ${result.action}`);
  console.log(`Reason: ${result.reason}`);
  console.log("Scores:", result.scores);
});

Multi-Dimension Scoring: One Pass, Many Questions

The power of a decision engine is evaluating multiple independent questions simultaneously without prompt chaining. 

// Multi-dimension routing: classify content for different audiences simultaneously
class ContentRouter {
  constructor() {
    this.dimensions = {
      safetyRating:  ["safe", "borderline", "unsafe"],
      topicCategory: ["tech", "finance", "health", "entertainment", "other"],
      sentimentScore:["positive", "neutral", "negative"],
      urgency:       ["high", "medium", "low"]
    };
  }

  async route(content) {
    // In Jev: all four dimensions scored in one forward pass
    const scores = await this._scoreAllDimensions(content);

    return {
      route: this._determineRoute(scores),
      scores,
      reasons: this._explain(scores)
    };
  }

  _determineRoute(scores) {
    // Routing logic uses numbers, not parsed text
    if (scores.safetyRating.unsafe > 0.6)  return "block";
    if (scores.urgency.high > 0.7 &&
        scores.safetyRating.safe > 0.8)    return "priority_queue";
    if (scores.sentimentScore.negative > 0.7 &&
        scores.topicCategory.health > 0.5) return "escalate_to_support";
    return "standard_queue";
  }

  _scoreAllDimensions(content) {
    // Simulated — real Jev returns this in one API call
    return Promise.resolve({
      safetyRating:  { safe: 0.85, borderline: 0.10, unsafe: 0.05 },
      topicCategory: { tech: 0.70, finance: 0.15, health: 0.05, entertainment: 0.05, other: 0.05 },
      sentimentScore:{ positive: 0.60, neutral: 0.30, negative: 0.10 },
      urgency:       { high: 0.20, medium: 0.60, low: 0.20 }
    });
  }

  _explain(scores) {
    return Object.entries(scores).map(([dim, s]) => {
      const top = Object.entries(s).sort((a, b) => b[1] - a[1])[0];
      return `${dim}: ${top[0]} (${(top[1] * 100).toFixed(0)}%)`;
    });
  }
}

const router = new ContentRouter();
router.route("New AI framework released with improved performance")
  .then(r => {
    console.log("Route:", r.route);
    console.log("Reasons:", r.reasons);
  });

When to Apply the Jev Pattern

  • Classification pipelines: content moderation, spam detection, sentiment analysis at scale.
  • Routing decisions: ticket triage, support escalation, A/B assignment based on user signals.
  • Risk scoring: fraud detection, credit scoring, anomaly flagging — where a probability matters more than an explanation.
  • Agent gate conditions: pre-flight checks before expensive tool calls — "should this agent proceed?"
  • Compound conditions: decisions that require evaluating 3+ dimensions simultaneously without prompt chaining.

When NOT to use it

  • When the user needs an explanation, not just a decision — use an LLM.
  • When outcome categories cannot be defined upfront — use generative models.
  • When the branching logic itself is complex and context-dependent — use an agent with reasoning.

Integrating Decision Engines into Agent Systems

Decision engines like Jev work as pre-flight gates in agentic workflows — cheap to run, no token generation overhead, and the results feed directly into control flow. 

// Agent workflow with Jev-style decision gate
class AgentWorkflow {
  constructor(decisionEngine, llmClient) {
    this.gate = decisionEngine;
    this.llm  = llmClient;
  }

  async processDocument(doc) {
    // Gate 1: Is this worth processing? (cheap score, no generation)
    const relevanceScores = await this.gate.score({
      docType: doc.type,
      wordCount: doc.wordCount,
      hasStructuredData: doc.hasTable || doc.hasJson
    });

    if (relevanceScores.irrelevant > 0.8) {
      return { status: "skipped", reason: "low relevance score" };
    }

    // Gate 2: What workflow path? (score → route, no LLM call yet)
    const routeScores = await this.gate.score({ content: doc.summary });
    const workflow = this._selectWorkflow(routeScores);

    // Only now invoke the expensive LLM for the matched workflow
    const result = await this.llm.process(doc, workflow);
    return { status: "processed", workflow, result };
  }

  _selectWorkflow(scores) {
    if (scores.financial > 0.7)   return "financial_extraction";
    if (scores.legal > 0.7)       return "legal_review";
    if (scores.technical > 0.7)   return "technical_summary";
    return "general_processing";
  }
}

// Result: decision gates run at 1/10th the cost of LLM calls
// Only qualified documents trigger expensive model invocations

Key Takeaway

When your downstream code needs to branch on a decision, return numbers — not words. Jev's architecture pattern (state + questions → scores → threshold check → code branch) keeps the branching logic in regular code where it belongs, eliminates fragile text parsing, evaluates all dimensions in one pass, and reduces cost by avoiding full token generation. Apply it wherever you need classification, routing, or gating in a pipeline — especially as pre-flight checks in agentic workflows before expensive LLM calls.
