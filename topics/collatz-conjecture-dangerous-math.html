The Collatz Conjecture — The Most Dangerous Problem in Math

A two-rule problem any 10-year-old can understand that has defeated every mathematician since 1937. Why it's "dangerous" — it looks solvable, absorbs lifetimes, and Paul Erdős warned colleagues to avoid it. With a JavaScript visualiser so you can play with it yourself.

The Collatz Conjecture has exactly two rules. You could explain them to a child in 30 seconds. It has been unsolved since 1937. Every positive integer anyone has ever tried eventually reaches 1, but no one can prove it must — and current mathematics may not have the tools to do so.

Core idea: Mathematical simplicity does not imply mathematical tractability. The Collatz problem proves that a statement can be trivially checkable for any specific number yet fundamentally unprovable in general — a gap that breaks intuition and careers.

Story · The career trap

Paul Erdős — arguably the most prolific mathematician of the 20th century, who co-authored papers with 511 collaborators — said of the Collatz Conjecture: "Mathematics is not yet ready for such problems." He also reportedly said that if someone admits in public they are working on it, there is something wrong with them.

The problem is dangerous not because it's hard in an obvious way, but because it looks like it should be easy. It has absorbed months of serious mathematicians who were sure they were close. The simplicity is the trap.

The rules

Two rules. One unsolved problem.

Rule 1: If the number is even → divide by 2 Rule 2: If the number is odd → multiply by 3, then add 1 Starting at 6: 6 ÷2→ 3 ×3+1→ 10 ÷2→ 5 ×3+1→ 16 ÷2→ 8 ÷2→ 4 ÷2→ 2 ÷2→ 1 Starting at 27: (takes 111 steps, peaks at 9,232) 27 → 82 → 41 → 124 → 62 → 31 → 94 → 47 → 142 → ... → 1

The conjecture (unproven claim): no matter what positive integer you start with, you will always eventually reach 1. Verified computationally for all numbers up to at least 268 (~295 quintillion). Still unproven in general.

Why 27 is notorious: Starting from 27, the sequence shoots up to 9,232 before finally collapsing to 1 — 111 steps later. Numbers nearby (26, 28) take far fewer steps. The behaviour has no obvious pattern.

JavaScript Example 
// Generate the full Collatz sequence for any starting number
function collatz(n) {
  if (!Number.isInteger(n) || n < 1) throw new RangeError("n must be a positive integer");
  const sequence = [n];
  while (n !== 1) {
    n = n % 2 === 0 ? n / 2 : 3 * n + 1;
    sequence.push(n);
  }
  return sequence;
}

// Stats for a starting number
function collatzStats(start) {
  const seq = collatz(start);
  return {
    start,
    steps: seq.length - 1,
    peak: Math.max(...seq),
    peakStep: seq.indexOf(Math.max(...seq)),
    sequence: seq,
  };
}

// Find which numbers take the most steps up to N
function longestCollatz(upTo) {
  let best = { start: 1, steps: 0 };
  for (let i = 2; i <= upTo; i++) {
    const steps = collatz(i).length - 1;
    if (steps > best.steps) best = { start: i, steps };
  }
  return best;
}

// Examples
console.log(collatzStats(27));
// { start: 27, steps: 111, peak: 9232, peakStep: 76, sequence: [...] }

console.log(collatzStats(6));
// { start: 6, steps: 8, peak: 16, peakStep: 4, sequence: [6,3,10,5,16,8,4,2,1] }

console.log(longestCollatz(1000));
// { start: 871, steps: 178 } — 871 takes 178 steps despite being less than 1000

// BigInt version for large numbers (JS numbers lose precision above 2^53)
function collatzBig(n) {
  n = BigInt(n);
  const sequence = [n];
  while (n !== 1n) {
    n = n % 2n === 0n ? n / 2n : 3n * n + 1n;
    sequence.push(n);
  }
  return sequence;
}

// Try a large number
const big = collatzBig(10n ** 15n + 7n);
console.log(`${big.length - 1} steps to reach 1`);

One interesting observation you can verify: even numbers with simple factorisations (powers of 2) reach 1 very quickly. It's the odd numbers — especially those where 3n+1 is divisible by a high power of 2 — that produce the longest sequences.

Why it's unsolved

What makes it hard

  • No algebraic structure to exploit. The rule switches between multiplication/division based on parity — a property that destroys the algebraic regularity most proofs rely on.
  • It's essentially a dynamical systems problem. The sequence is a trajectory in a discrete dynamical system, and such systems can behave chaotically even under simple rules.
  • Computational verification isn't a proof. Checking 268 cases proves nothing about 268+1. Mathematics requires an argument that works for all integers, not a big list.
  • Current tools may be insufficient. Erdős's belief was that the problem isn't hard in the sense of requiring more cleverness — it may be hard in the sense of requiring fundamentally new mathematics that doesn't exist yet.

Key Takeaway

The Collatz Conjecture sits at the intersection of number theory, dynamical systems, and computability theory — and falls squarely into none of them. Its value as a learning story isn't "this is important for your work." It's a reminder that the gap between "I can verify this for any specific case" and "I can prove this for all cases" is not a gap of computation but of mathematical structure. Some problems are easy to state, easy to check, and currently impossible to prove. That gap is what makes mathematics interesting.
