AI, Agents, and MCP Foundations

A practical first-principles map: what AI models do, what agents add on top, and how MCP lets agents talk to tools and systems with clean schemas.

If LLMs are the "reasoning engine," agents are the workflow layer around that engine. MCP is the interface contract that lets those workflows safely call tools and read resources.

Mental model: model = brain, agent = behavior loop, MCP = tool protocol.

What changes from plain prompt to agent system

  • Prompt-only: one input, one output, no durable state.
  • Agent: plans steps, calls tools, checks results, retries, and continues.
  • MCP-enabled agent: discovers capabilities via schema, then executes tools safely.

Core components you should recognize

  • Model selection (quality, speed, cost).
  • Tool execution layer (timeouts, retries, validation).
  • Memory layer (session memory and optional long-term retrieval).
  • Guardrails (policy checks, redaction, output constraints).
  • Observability (traces, logs, eval metrics, failure taxonomy).

Key takeaway

Learn these in order: LLM basics, then agent loops, then MCP contracts. That sequence keeps your builds understandable and avoids "magic" behavior you cannot debug.

The Full AI Stack: Layer by Layer

Each layer in the AI stack extends the previous one. None replace what's below — the stack is cumulative, not substitutive.

LayerWhat It DoesKey Limitation Without Next Layer
Deep LearningNeural networks learn patterns from data — not hand-written rulesOnly recognizes patterns; can't generate fluent language
LLMMassive NLP scale — generates contextual language, not just classifiesNo real-time data, no company-specific knowledge, no actions
GenAISummarization and pattern completion — writes, codes, answers questionsOnly knows training data; hallucinated facts cannot be grounded
RAGRetrieves relevant documents at query time; constrains (not expands) model knowledgeCan answer but cannot act; no external integrations
MCP / ToolsStandardized interfaces to external systems — CRMs, APIs, databasesOne model, one task; cannot delegate to specialists
Agentic AIOrchestration pattern: one lead agent delegates to specialized workers, each with own RAG + tools—

Mental model: RAG constrains knowledge. MCP extends actions. Agentic AI distributes work. Each layer solves the bottleneck of the one before it.

RAG: Grounds Responses, Doesn't Expand Capability

A common misunderstanding: RAG "gives the model more knowledge." More precisely, RAG constrains the model to respond from actual documents, reducing hallucination. It does not make the model smarter — it makes the model more reliably grounded.

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

async function retrieveDocuments(query, topK = 3) {
  const docs = [
    { id: "doc1", text: "Our return policy allows 30-day returns on all items.", score: 0.92 },
    { id: "doc2", text: "Electronics have a 15-day return window.", score: 0.87 },
    { id: "doc3", text: "Sale items are final sale — no returns accepted.", score: 0.71 }
  ];
  return docs.slice(0, topK);
}

async function ragQuery(userQuestion) {
  // Step 1: Retrieve relevant context
  const docs = await retrieveDocuments(userQuestion);
  const context = docs.map(d => d.text).join("\n\n");

  // Step 2: Pass context to model — model responds ONLY from these documents
  const response = await client.messages.create({
    model: "claude-haiku-4-5-20251001",
    max_tokens: 512,
    messages: [{
      role: "user",
      content: `Answer the question using ONLY the context below.
If the answer is not in the context, say "I don't have that information."

Context:
${context}

Question: ${userQuestion}`
    }]
  });

  return response.content[0].text;
}

ragQuery("Can I return a laptop I bought 20 days ago?")
  .then(answer => console.log(answer));
// → Uses "Electronics have a 15-day return window" — refuses to hallucinate a different policy
