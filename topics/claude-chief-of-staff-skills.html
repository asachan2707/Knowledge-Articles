I Turned Claude Code Into My Chief of Staff — One Folder, 6 Skills

How to build a persistent HQ folder that gives Claude permanent context about you, your work, and your workflows — eliminating the 200-word context dump at the start of every session. Includes the full folder structure, example skills, and how to wire MCP connections to your calendar and email.

Most people use Claude Code like a stateless API: open a session, paste context, ask the question, close. Next day, repeat from scratch. The Chief of Staff pattern flips this: you build persistent context into a folder structure that Claude reads automatically, so every session starts with full awareness of who you are, what you're working on, and how you like to work.

Core idea: You are the context window's unpaid intern when you re-paste the same 200 words every session. An HQ/ folder with a strong CLAUDE.md and six well-designed skills makes you the beneficiary instead.

Story · Before and after

Before: every morning, a developer opened Claude Code and typed the same paragraph: who he is, his current project, his coding preferences, his company's tech stack. Three minutes wasted before the actual work. One day multiplied by 200 working days is 10 hours of context-pasting per year.

After the HQ folder: Claude opens every session knowing his stack, his active projects, his decision log, and his personal working style. The standup skill generates his daily update in 30 seconds from his git log and calendar. The 10 hours came back.

The folder structure

The HQ folder layout

HQ/ ├── CLAUDE.md # persistent identity + context Claude always reads ├── .claude/ │ └── skills/ │ ├── standup.md # /standup — generate daily update │ ├── plan-week.md # /plan-week — review calendar, set priorities │ ├── write-pr.md # /write-pr — generate PR description from git diff │ ├── debrief.md # /debrief — end-of-day reflection + decision log │ ├── research.md # /research — deep-dive on any topic, STORM method │ └── email-draft.md # /email-draft — draft any email with context ├── context/ │ ├── projects.md # active projects, status, blockers │ ├── decisions.md # decision log — why we chose X over Y │ └── people.md # key contacts, roles, communication style └── .mcp.json # MCP server connections: calendar, email, Slack
The 6 skills

What each skill does

/standup

Reads your git log (last 24h), checks your calendar for yesterday's meetings, and generates a standup update in your team's preferred format. One command, 30 seconds.

/plan-week

Reads your calendar for the coming week, cross-references your projects.md for blockers and deadlines, and produces a prioritised weekly plan with time blocks suggested.

/write-pr

Reads git diff main, infers intent from commit messages and code changes, and writes a full PR description with context, test plan, and screenshots section.

/debrief

End-of-day skill. Reads today's activity, asks 3 reflection questions, updates decisions.md with any choices made, and prepends a summary to projects.md status.

/research

Deep-dive research skill using the STORM method (multi-perspective, cited). Output is a structured brief with a defensible claim, not just collected facts.

/email-draft

Reads context from people.md (recipient's communication style), CLAUDE.md (your voice), and the provided topic — drafts an email in your tone with the right level of formality.

The skill file format

What a skill file looks like

Skill files live in .claude/skills/ as Markdown files. The frontmatter controls when Claude activates the skill; the body is the instruction set.

JavaScript Example — MCP wiring for calendar access 
// .mcp.json in your HQ folder — connects Claude to external tools
// (Google Calendar, email, Slack via MCP servers)
{
  "mcpServers": {
    "google-calendar": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-google-calendar"],
      "env": { "GOOGLE_OAUTH_CREDENTIALS": "~/.credentials/google.json" }
    },
    "gmail": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-gmail"],
      "env": { "GOOGLE_OAUTH_CREDENTIALS": "~/.credentials/google.json" }
    }
  }
}

// With this wired, the /standup skill can do:
// "Check my calendar for yesterday's meetings via the google-calendar MCP tool,
//  then combine with git log to generate my standup."

// Example CLAUDE.md personal context block
const claudeMdTemplate = `
## Identity
- Name: [Your name]
- Role: [Senior Engineer / PM / etc.]
- Team: [Team name]
- Timezone: [UTC+X]

## Current Projects
See context/projects.md for live status.

## Tech Stack
- Backend: Node.js + Express + PostgreSQL
- Frontend: React + Vite
- Infra: AWS ECS, Terraform
- AI: Anthropic Claude API

## Working Style
- I prefer concise responses — 3-5 bullets over 3 paragraphs
- Always show me the code, not just the explanation
- When I ask "what should I do?", give me a recommendation, not options
- Default language for examples: JavaScript (ES2022+)

## Communication
- Standups: daily at 9am, Slack #team-eng
- PRs: always include test plan + screenshots
- Decisions: log to context/decisions.md

## Skills available
/standup — daily standup from git + calendar
/plan-week — weekly priorities from calendar + projects
/write-pr — PR description from git diff
/debrief — end-of-day reflection
/research — deep research with STORM method
/email-draft — draft emails in my voice
`;
The compounding effect: Skills load only when invoked — they don't consume context window space just by existing. A 500-line skill file costs zero tokens until you run /research. This means you can build rich, detailed skills without worrying about bloating your context on every session.
Practical checklist

How to set up your HQ in an afternoon

  • Create HQ/CLAUDE.md — write your identity, stack, working style, and active projects. Be specific enough that Claude could introduce you to a new colleague.
  • Start with two skills: /standup and /write-pr — these have the clearest inputs (git log, diff) and the most daily value.
  • Add context/projects.md with one line per active project: name, status, next milestone, blockers.
  • Wire MCP connections only after the folder is useful without them — don't let setup friction stop the core habit.
  • Use /debrief once a week to update projects.md — this keeps your context fresh without manual maintenance.

Key Takeaway

The Chief of Staff pattern works because it separates persistent context (who you are, what you're working on) from session-specific tasks. That separation is what allows Claude to behave like a genuine collaborator rather than a forgetful assistant. The HQ folder is the minimum viable persistent context: one strong CLAUDE.md, six well-scoped skills, and a context directory you maintain weekly. The investment is one afternoon; the return is compounding daily.
