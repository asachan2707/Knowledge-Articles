Expose Your Local Spring Boot API to the Internet with ngrok

When your API runs at localhost:8080, it's invisible to the internet — webhooks, mobile testing, and teammate demos all need a public URL. ngrok creates a secure tunnel that solves this in under two minutes, without cloud deployment.

Why localhost Isn't Enough

Local development works great until your application needs to receive data from the internet. Payment webhooks, OAuth callbacks, mobile app testing, and live demos all require a URL that external services can reach — and localhost:8080 is not one.

Payment Webhooks

Stripe, Razorpay, PayPal all need to POST to your endpoint to confirm payment status.

OAuth Callbacks

OAuth providers redirect to a callback URL — it must be publicly reachable.

Mobile App Testing

Test your API from a real phone on a different network without cloud deployment.

Teammate Demos

Share work in progress with a remote colleague instantly — no staging environment needed.

Third-Party Integrations

Slack apps, GitHub webhooks, CI/CD integrations all need a reachable endpoint.

API Testing Tools

Some hosted testing tools need to call your API from their cloud — not your laptop.

How ngrok Works

ngrok creates a secure tunnel from a public endpoint to your local machine. The traffic flows:

Flow: External Service → ngrok Public URL → ngrok Secure Tunnel → localhost:8080 → Your Spring Boot App

Your app never exposes itself directly — ngrok's infrastructure handles TLS termination, authentication, and the connection relay. Your local firewall settings don't need to change.

Step-by-Step Setup

1

Build a minimal Spring Boot REST endpoint

Start with a working local API. Port 8080 is the Spring Boot default.

2

Install ngrok

Download from ngrok.com or via package manager: brew install ngrok (macOS) or choco install ngrok (Windows).

3

Authenticate ngrok

Sign up at ngrok.com, get your auth token, run: ngrok authtoken YOUR_TOKEN

4

Start the tunnel

With your Spring Boot app running: ngrok http 8080. You'll see a public URL like https://abc123.ngrok-free.app

5

Configure your webhook provider

Paste the ngrok URL as the webhook endpoint in your payment provider, OAuth app, or Slack app settings.

// Minimal Spring Boot webhook receiver (Java)
@RestController
@RequestMapping("/webhooks")
public class WebhookController {

    @PostMapping("/stripe")
    public ResponseEntity<String> handleStripeEvent(
            @RequestBody String payload,
            @RequestHeader("Stripe-Signature") String sigHeader) {

        // Validate webhook signature first (security!)
        if (!validateStripeSignature(payload, sigHeader)) {
            return ResponseEntity.status(400).body("Invalid signature");
        }

        // Parse and process the event
        try {
            JsonNode event = objectMapper.readTree(payload);
            String eventType = event.get("type").asText();

            switch (eventType) {
                case "payment_intent.succeeded":
                    handlePaymentSuccess(event);
                    break;
                case "payment_intent.failed":
                    handlePaymentFailure(event);
                    break;
            }

            return ResponseEntity.ok("Received");
        } catch (Exception e) {
            return ResponseEntity.status(500).body("Processing error");
        }
    }

    private boolean validateStripeSignature(String payload, String sigHeader) {
        // Always validate webhook signatures — ngrok doesn't protect you from
        // forged requests once your URL is public
        String secret = System.getenv("STRIPE_WEBHOOK_SECRET");
        try {
            Event event = Webhook.constructEvent(payload, sigHeader, secret);
            return event != null;
        } catch (SignatureVerificationException e) {
            return false;
        }
    }
}

Programmatic Tunnels with ngrok SDK (Node.js)

For Node.js projects, the ngrok SDK lets you create tunnels programmatically — useful for test setups, CI environments, and development scripts. 

import ngrok from "@ngrok/ngrok";
import express from "express";

const app = express();
app.use(express.json());

// Webhook handler
app.post("/webhook", (req, res) => {
  console.log("Webhook received:", req.body);

  // Validate signature before processing
  const signature = req.headers["x-hub-signature-256"];
  if (!validateSignature(req.rawBody, signature, process.env.WEBHOOK_SECRET)) {
    return res.status(401).json({ error: "Invalid signature" });
  }

  // Process the event
  processWebhookEvent(req.body);
  res.json({ received: true });
});

// Health check — useful to verify tunnel is working
app.get("/health", (req, res) => {
  res.json({ status: "ok", timestamp: new Date().toISOString() });
});

async function startWithTunnel() {
  const PORT = 3000;
  app.listen(PORT);

  // Create ngrok tunnel programmatically
  const tunnel = await ngrok.forward({
    addr:     PORT,
    authtoken: process.env.NGROK_AUTHTOKEN,
    // Optional: custom domain (paid plan)
    // domain: "my-api.ngrok.io"
  });

  const publicUrl = tunnel.url();
  console.log(`Local server: http://localhost:${PORT}`);
  console.log(`Public URL:   ${publicUrl}`);
  console.log(`Webhook URL:  ${publicUrl}/webhook`);

  // Print tunnel info for easy copy-paste into webhook settings
  console.log("\nCopy this URL to your webhook provider:");
  console.log(`  ${publicUrl}/webhook`);

  return tunnel;
}

function validateSignature(payload, signature, secret) {
  if (!signature || !secret) return false;
  const crypto = require("crypto");
  const expected = "sha256=" + crypto
    .createHmac("sha256", secret)
    .update(payload)
    .digest("hex");
  return crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
}

function processWebhookEvent(event) {
  console.log(`Processing event type: ${event.type || event.event}`);
  // Your business logic here
}

startWithTunnel().catch(console.error);

ngrok's Built-in Request Inspector

One of ngrok's most useful features for development: the web inspector at http://localhost:4040 shows every request that comes through the tunnel — headers, body, response, and timing. 

// Programmatically access ngrok's inspection API
async function getRecentRequests() {
  const response = await fetch("http://localhost:4040/api/requests/http");
  const data = await response.json();

  data.requests.forEach(req => {
    console.log(`${req.request.method} ${req.request.uri}`);
    console.log(`Status: ${req.response?.status_code ?? "pending"}`);
    console.log(`Duration: ${req.duration}ms`);
    if (req.request.raw) {
      const body = Buffer.from(req.request.raw, "base64").toString();
      console.log("Body:", body.substring(0, 200));
    }
    console.log("---");
  });
}

// Also useful: replay failed requests during debugging
async function replayRequest(requestId) {
  const response = await fetch(`http://localhost:4040/api/requests/http/${requestId}/replay`, {
    method: "POST"
  });
  return response.ok;
}

// Call during development to inspect last 10 webhook calls
setInterval(getRecentRequests, 5000);
Replay-on-failure: The ngrok web UI lets you replay any failed webhook request. This is invaluable when debugging webhook processing logic — you can trigger the exact same payload repeatedly without re-generating a payment or OAuth event.

Limitations and Security Notes

Free tier limitations:
  • Random URL changes every session (no persistent domain)
  • 40 connections/min rate limit
  • 1 concurrent tunnel
  • Not suitable for production traffic
  • Always validate webhook signatures. ngrok makes your endpoint public — without signature validation, anyone can POST to your webhook URL. Every reputable webhook provider (Stripe, GitHub, Slack) provides a signature mechanism.
  • Don't commit your ngrok auth token. Store it in environment variables: NGROK_AUTHTOKEN.
  • ngrok is for development only. For staging/production: deploy to a real server, use a load balancer, or use serverless functions for webhook handlers.
  • The URL changes on every restart (free plan). Update your webhook URL configuration every development session. Paid plans offer stable custom domains.
  • Monitor the inspector. The localhost:4040 inspector reveals your request/response details — don't leave it exposed if working in a shared network.

Key Takeaway

ngrok solves a real development friction point: you need a public HTTPS URL to test webhooks, OAuth flows, or mobile integrations, but you're in the middle of development and not ready to deploy. The two-minute setup (ngrok http 8080) gets you a working public URL immediately. The built-in inspector and request replay make webhook debugging significantly faster than print-debugging alone. Always validate webhook signatures — the public URL means anyone can POST to it, and the signature is your only protection against forged events.
