A language model does one thing: given everything so far, produce a probability distribution over the next token and sample one. Everything impressive and everything dangerous about it follows from that.

Core idea: Fluency and hallucination are the same mechanism: the model continues patterns toward what is likely, and “likely” is not “true”, especially in specifics.

Story · Texting with only the suggestion bar

The lesson opens with a game many people played: compose a message to a friend using only your phone’s suggested next words. It felt like a "Me-bot" that knew your voice. In reality the mechanism behind that bar was a table of word-to-next-word counts, an idea Andrey Markov published in 1906 and that powered phone keyboards (SwiftKey, then Apple’s QuickType) around 2010. Modern language models replace the table with a neural network but keep the same final move: produce a probability distribution over what comes next, then sample from it.

Lesson 4

"A vastly sophisticated autocomplete"

The course frames generative AI as closer to autocomplete than to a search engine: it composes an answer one token at a time, guided by what usually follows. That single trait explains both its fluency and its tendency to hallucinate.

ZoneWhat it looks likeWhy
CapabilitySummarising, reformatting, explaining common conceptsHeavily trodden patterns; the likely continuation is also the correct one
LimitationNovel or sparse territory; anything separating "true" from "sounds true"Likelihood and truth diverge; nothing in the mechanism checks facts
Fabrication hot-spotNames, dates, statistics, citations, URLs, quotesSpecificity needs a unique correct token string; many plausible ones exist

Product mitigations that push the limitation outward

  • Citations — claims linked to retrieved sources you can open.
  • Uncertainty signalling — the product tells you when it is unsure.
  • Constrained generation — outputs forced into a schema or allowed set.
  • Generator–verifier loops — a second pass checks the first.

4D link: this is the foundation for Discernment. Knowing an output was generated tells you what scrutiny it needs.

Lesson 5 · Try It Out

Build a Markov text predictor, then compare it to an LLM

The hands-on simulation walks through five steps. The page sets the model up with five short "text messages" and builds up from there:

  1. Train — tally which word follows which. The result is a frequency table (transition matrix). Normalising each row gives a probability distribution.
  2. Sample — pick the next word from a row. "Sampling" is the same term used for Claude and other LLMs.
  3. Scale up — five messages give 17 unique words and 24 transitions; more data gives a bigger, richer table, but the table’s rows grow with vocabulary (the "exponential wall" the lesson mentions for longer contexts).
  4. Turn the knobs — greedy highest-probability, proportional sampling, boosting likely words (temperature), probability thresholds (top-p), top-N only (top-k), or random "goblin mode".
  5. Bridge to LLMs — same output type (a distribution over next tokens), radically different internals.
StepMarkov chainLLM
1. Read contextLast word onlyEntire conversation so far
2. Compute distributionLook up one row in a tableForward pass through billions of parameters (attention, embeddings, feed-forward layers…)
3. Sample next tokenPick from the rowSame process

Training is where they diverge most: the table’s one-row-per-context scheme explodes combinatorially, while a neural network learns a compact function that generalises across contexts. The trade is explainability (you can read a table) for capability.

Code

Runnable Markov chain with temperature, top-k and top-p

This reproduces the lesson’s exercise with its five messages. Greedy decoding (top-k = 1) always yields the same sentence; plain sampling produces different, equally "plausible" continuations per seed — the same variation you see when re-asking an LLM in a fresh conversation.

JavaScript Example 
// Markov-chain "autocomplete": the 100%-interpretable cousin of an LLM's next-token step.
const messages = [
  'i think we should probably ship it',
  'i think that sounds good',
  'i think we should probably wait',
  'we should check with the team',
  'that sounds good to me',
];

// 1. "Training" = tally which word follows which (a frequency table / transition matrix).
const table = new Map();
for (const msg of messages) {
  const words = msg.split(' ');
  for (let i = 0; i < words.length - 1; i++) {
    const row = table.get(words[i]) ?? new Map();
    row.set(words[i + 1], (row.get(words[i + 1]) ?? 0) + 1);
    table.set(words[i], row);
  }
}

// 2. Normalise a row into a probability distribution.
function distribution(word) {
  const row = table.get(word);
  if (!row) return [];
  const total = [...row.values()].reduce((a, b) => a + b, 0);
  return [...row].map(([w, n]) => ({ word: w, p: n / total })).sort((a, b) => b.p - a.p);
}

// 3. The "knobs": temperature, top-k, top-p reshape the distribution before sampling.
function sample(dist, { temperature = 1, topK = Infinity, topP = 1 } = {}, rand = Math.random) {
  let d = dist.slice(0, topK);                                   // top-k: keep N best
  let cum = 0;
  d = d.filter((x, i) => (i === 0 || cum < topP) && ((cum += x.p), true)); // top-p: smallest set covering p
  const w = d.map((x) => Math.pow(x.p, 1 / temperature));        // temperature: <1 sharpens, >1 flattens
  const sum = w.reduce((a, b) => a + b, 0);
  let r = rand() * sum;
  for (let i = 0; i < d.length; i++) if ((r -= w[i]) <= 0) return d[i].word;
  return d.at(-1).word;
}

// Tiny seeded RNG (mulberry32) so the output is reproducible.
const seeded = (s) => () => ((s = (s + 0x6d2b79f5) | 0), (((t) => ((t ^ (t >>> 14)) >>> 0) / 4294967296)(Math.imul(s ^ (s >>> 15), 1 | s))));

console.log('after "think":', distribution('think'));
console.log('after "should":', distribution('should'));

function generate(start, opts, seed, maxWords = 8) {
  const rand = seeded(seed);
  const out = [start];
  while (out.length < maxWords) {
    const dist = distribution(out.at(-1));
    if (!dist.length) break;
    out.push(sample(dist, opts, rand));
  }
  return out.join(' ');
}
console.log('greedy (top-k=1):', generate('i', { topK: 1 }, 1));
for (const seed of [1, 2, 3]) console.log(`temp=1 seed=${seed}:`, generate('i', { temperature: 1 }, seed));

Architect's note

The knobs, precisely

  • Temperature rescales the distribution: logits are divided by T before softmax. T<1 sharpens toward the mode, T>1 flattens toward uniform. T→0 is greedy decoding. (The toy code uses p1/T, which is identical when logits are log-probabilities.)
  • Top-k keeps only the k most likely tokens; top-p (nucleus) keeps the smallest set whose cumulative probability reaches p. Top-p adapts to how peaked the distribution is; top-k does not.
  • Even a deterministic setting is not a truth guarantee: greedy decoding picks the most likely token, not the correct one.
  • Cost shape: self-attention work grows roughly quadratically with context length, while the KV cache grows linearly in memory. That is why context is a priced, bounded resource (see Working Memory).
Exercise

The verification test

  • Pick your highest-expertise task and write down five facts you know are right (a title, a date, a figure, a quote, a URL).
  • Probe 1 (capability zone): ask for an explanation of a well-known concept; expect fluent, mostly correct output.
  • Probe 2 (specificity): ask for five checkable specifics (three sources, an author, exact figures, a URL). Verify each, score out of five, and note how confident it sounded when wrong.
  • Probe 3 (sampling): repeat Probe 2 in a fresh conversation; what changed is sampling at work.
  • Stretch: repeat Probe 2 with citations enabled (e.g. a research mode) and compare your score.

Reflect: would you have caught the fabrications in a field you do not know?

Checklist

Failure modes & verification habits

  • Treat every name, date, number, URL and quote as unverified until checked; the more precise the claim, the more it deserves a check.
  • Prefer tools that attach sources, and open at least a sample of them.
  • Ask for the same facts twice in separate sessions; disagreement is a cheap fabrication detector.
  • Use constrained output (JSON schema, enums) when the answer must come from a closed set.
  • For high-stakes claims, run a verifier pass or a human review, not another self-assessment from the same model.
FAQ

Frequently Asked Questions

Is an LLM just a Markov chain?

No. The sampling step is the same idea, but the context, the learned function and the capability are radically different. The Markov chain is a teaching model because it is fully inspectable.

Why does the same prompt give different answers?

Sampling. The model produces a distribution and picks from it; lower temperature narrows the spread but does not make the answer verified.

Why are citations and URLs the classic hallucination?

They demand one exact string. Many strings look right, and the mechanism rewards looking right.

Key Takeaway

Use AI hardest where the likely answer is the right answer (familiar patterns), and verify hardest where the answer must be a unique string (names, numbers, citations, URLs). A confident tone is part of the mechanism, not evidence for the claim.
