Build a Multi-LLM Gateway + Turn Your Laptop Into a Private AI Server

Two merged topics: how to build a provider-agnostic LLM gateway in JavaScript so switching from Anthropic to OpenAI to a local model is a one-line change — and how to set up a private Ollama AI server on any laptop in 30 minutes with no GPU required.

JS Example✓ Multi-provider gateway, Ollama client

Building your application around a single LLM provider is the fastest way to become hostage to their pricing, availability, and API changes. A gateway layer decouples your application from any specific provider — your code calls one function, the gateway handles the provider-specific headers, authentication, and response format differences.

Core idea: Abstract provider differences behind a single generate(provider, model, messages) interface. Adding a new provider becomes a one-function addition. Switching the whole app to a different model takes one config change.

Story · The provider lock-in trap

A startup built their AI product entirely on GPT-4. When OpenAI changed their rate limits and pricing in Q1 2026, the team needed two weeks to migrate to Claude — every API call had different headers, message formats, and system prompt handling. A gateway layer would have made it a 4-hour change. They paid the price of skipping abstraction.

Part 1: Multi-LLM Gateway

Gateway architecture

Your application

  • Always calls generate(provider, model, messages)
  • Receives { provider, model, text } back
  • Never touches provider-specific code
  • Switch provider = change one string

Gateway layer

  • Provider-specific auth headers
  • Message format normalisation
  • System message handling (Anthropic separates this)
  • Error normalisation across providers
  • Retry logic and fallback chains

Critical Anthropic difference: Unlike most providers, Anthropic requires system messages in a separate top-level field, not inline in the messages array. Your gateway must extract and re-route them.

JavaScript Example 
// Multi-provider LLM gateway in Node.js
const PROVIDERS = {
  anthropic: {
    url: "https://api.anthropic.com/v1/messages",
    headers: (key) => ({
      "x-api-key": key,
      "anthropic-version": "2023-06-01",
      "Content-Type": "application/json",
    }),
  },
  openai: {
    url: "https://api.openai.com/v1/chat/completions",
    headers: (key) => ({
      Authorization: `Bearer ${key}`,
      "Content-Type": "application/json",
    }),
  },
  together: {
    url: "https://api.together.xyz/v1/chat/completions",
    headers: (key) => ({
      Authorization: `Bearer ${key}`,
      "Content-Type": "application/json",
    }),
  },
  ollama: {
    url: "http://localhost:11434/api/chat",
    headers: () => ({ "Content-Type": "application/json" }),
  },
};

class LLMGateway {
  constructor(apiKeys = {}) {
    this.apiKeys = apiKeys;
  }

  async generate(provider, model, messages, options = {}) {
    provider = provider.toLowerCase().trim();
    const config = PROVIDERS[provider];
    if (!config) throw new Error(`Unknown provider: ${provider}`);

    const apiKey = this.apiKeys[provider] || process.env[`${provider.toUpperCase()}_API_KEY`];
    const headers = config.headers(apiKey);

    // Build provider-specific payload
    let payload;
    if (provider === "anthropic") {
      // Anthropic: extract system messages to top-level field
      const systemMessages = messages.filter((m) => m.role === "system");
      const chatMessages = messages.filter((m) => m.role !== "system");
      payload = {
        model,
        max_tokens: options.maxTokens ?? 1024,
        messages: chatMessages,
        ...(systemMessages.length && { system: systemMessages.map((m) => m.content).join("\n") }),
      };
    } else {
      // OpenAI-compatible (OpenAI, Together, Ollama)
      payload = { model, messages, max_tokens: options.maxTokens ?? 1024 };
    }

    const res = await fetch(config.url, {
      method: "POST",
      headers,
      body: JSON.stringify(payload),
      signal: AbortSignal.timeout(30_000),
    });

    if (!res.ok) {
      const err = await res.text();
      throw new Error(`${provider} API error ${res.status}: ${err}`);
    }

    const data = await res.json();

    // Normalise response format
    const text =
      provider === "anthropic"
        ? data.content?.find((b) => b.type === "text")?.text
        : data.choices?.[0]?.message?.content ?? data.message?.content;

    return { provider, model, text };
  }

  // Fallback chain: try providers in order until one succeeds
  async generateWithFallback(chain, messages, options = {}) {
    for (const { provider, model } of chain) {
      try {
        return await this.generate(provider, model, messages, options);
      } catch (err) {
        console.warn(`[gateway] ${provider}/${model} failed: ${err.message} — trying next`);
      }
    }
    throw new Error("All providers in fallback chain failed");
  }
}

// Usage
const gateway = new LLMGateway();

// Simple call
const result = await gateway.generate("anthropic", "claude-opus-4-8", [
  { role: "user", content: "Explain CAP theorem in one paragraph." },
]);

// With automatic fallback
const fallbackResult = await gateway.generateWithFallback(
  [
    { provider: "anthropic", model: "claude-opus-4-8" },
    { provider: "openai", model: "gpt-4o" },
    { provider: "ollama", model: "llama3.2" }, // free local fallback
  ],
  [{ role: "user", content: "Summarise this document." }]
);

console.log(result.text);
Part 2: Private AI Server on Your Laptop

Ollama setup in 30 minutes — no GPU required

Ollama runs quantised open-source models locally using CPU + Metal/CUDA if available. On an M-series Mac or a modern Intel/AMD laptop you can run capable models for free with no data leaving your machine.

Good models for CPU-only

  • llama3.2:3b — fast, low RAM (4 GB)
  • mistral:7b — strong reasoning, needs 8 GB
  • qwen2.5-coder:7b — best local coding model
  • phi3:mini — Microsoft, tiny but capable

Setup steps

  • Install: brew install ollama
  • Start server: ollama serve
  • Pull model: ollama pull llama3.2
  • Test: ollama run llama3.2
  • API available at http://localhost:11434
JavaScript Example 
// Connect to local Ollama — OpenAI-compatible API
import OpenAI from "openai"; // works with local Ollama too

const ollama = new OpenAI({
  baseURL: "http://localhost:11434/v1",
  apiKey: "ollama", // required by the client but ignored locally
});

async function askLocal(question, model = "llama3.2") {
  const response = await ollama.chat.completions.create({
    model,
    messages: [{ role: "user", content: question }],
    stream: true,
  });

  let fullText = "";
  process.stdout.write(`\n[${model}] `);
  for await (const chunk of response) {
    const delta = chunk.choices[0]?.delta?.content ?? "";
    process.stdout.write(delta);
    fullText += delta;
  }
  console.log();
  return fullText;
}

// Use the gateway to switch seamlessly between local and cloud
const gateway = new LLMGateway();

const answer = await gateway.generate(
  process.env.USE_LOCAL === "true" ? "ollama" : "anthropic",
  process.env.USE_LOCAL === "true" ? "llama3.2" : "claude-opus-4-8",
  [{ role: "user", content: "What is vector similarity search?" }]
);

console.log(answer.text);
RAM reality check: A 7B model needs ~8 GB of free RAM to run at reasonable speed. A 13B model needs ~16 GB. Running on a machine with less causes heavy swap I/O and makes the model painfully slow — use a 3B model if RAM is limited.
When to use local vs cloud

Decision guide

Use local (Ollama)

  • Sensitive data that must not leave your machine
  • High-volume tasks where API costs add up
  • Offline development environments
  • Iterating rapidly on prompts without cost anxiety

Use cloud (Anthropic/OpenAI)

  • Complex reasoning requiring the best models
  • Long context windows (>32K tokens)
  • Production applications with SLA requirements
  • Tasks where model quality directly affects revenue

Key Takeaway

The gateway pattern and local model infrastructure are two sides of the same coin: provider flexibility. The gateway lets you switch cloud providers in one line; Ollama lets you run the whole stack locally for free. Together, they mean you can develop, test, and prototype without cloud API costs, then deploy to the best available model for production — all without changing a line of your application code.
