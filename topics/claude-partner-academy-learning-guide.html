Core 3
Claude Platform & Model Foundations
Four decisions that set the quality ceiling before you write a prompt: entry point, capability features, model, and context. On every path (Associate 3/8, Developer 3/9, Architect 3/10, FDE 3/10).
FREE 59 min Associate Foundations prep Haiku · Sonnet · Opus · Context / memory

Learning objectives

  • Select the appropriate Claude entry point and feature set for a professional task
  • Differentiate Haiku, Sonnet, and Opus by capability and task fit
  • Match model to quality, speed, and volume trade-offs
  • Manage context limits and use memory to keep continuity across sessions
For recurring work and deliverables that need a high-quality review, these four decisions determine whether the session builds on prior work or requires constant re-setup.

Prompting & Task Execution
Prompting as a communication discipline. Same request, different phrasing → different quality. Anchored on Description from the 4D framework.
53 min Associate Foundations prep Description · Task decomposition

Why it exists

“Write something about our Q3 results” → generic paragraph. Specify audience, the three results that matter, format, and length → a draft ready to share.

Learning objectives

  • Create effective prompts for business and technical tasks using a repeatable component structure
  • Apply task decomposition to complex, multi-part requests
  • Iterate prompts diagnostically to improve output quality
  • Adapt strategy to task type: analysis, research, drafting, or brainstorming

Architect 7 · Path course 8/10
Product Foundations
Start here before advising a client. What Claude Code is (terminal agent, not IDE plugin), Haiku/Sonnet/Opus trade-offs, four deployment paths vs the client's cloud posture. Scenario check at the end.
29 min + 15 min practice Claude Code Partner Badge 4 deployment paths · Model selection

Three client-conversation questions

1
What Claude Code is — runs in the terminal, works agentically (read files, write code, run commands, multi-step). That posture shapes scope, config, and what you tell IT.
2
Model selection — Haiku / Sonnet / Opus. Cost, speed, reasoning depth. Most deployments start with Sonnet; the recommendation needs a reason.
3
Deployment path — Claude for Enterprise direct · Amazon Bedrock · Google Vertex AI · Microsoft Foundry. Driven by cloud commitments, procurement, compliance, who manages seats/budgets.

Curriculum

  • What Claude Code is and how it behaves in a codebase
  • Claude family model selection and tradeoffs
  • Platform options at a glance: Enterprise, API, deployment paths
Closes with a 5-question scenario check: three client profiles → pick model + deployment. Orientation, no hands-on artifact.

Architect 8 · Path course 9/10
Deployment Architecture
Hard to reverse after rollout. Four paths, parity gaps, proxy config, LLM gateway, data residency / ZDR. Artifact: Deployment Decision Doc.
1h 16m + 50 min practice Claude Code Partner Badge Parity gaps · Gateway · ZDR

What it determines

Who bills the client, how developers authenticate, where usage data lands, which features exist. Land this in the pre-kickoff window, not as a change request.

Curriculum

  • Deployment decision framework — four questions: cloud, buying route, compliance, who manages users/budgets
  • Feature parity gaps — WebSearch, ZDR eligibility, bundled Claude web access often missing on cloud-native routes. Surface before contract.
  • Corporate proxy: HTTPS_PROXY, HTTP_PROXY, TLS inspection
  • LLM gateway: centralized auth, per-team chargeback, spend controls
  • Data residency, compliance posture, ZDR eligibility
Practice: recommend a path for a sample client (cloud, parity, compliance). That write-up is the Deployment Decision Doc you reuse on live engagements.

Architect 9 · Path course 10/10
Delivery Methodology
Technical deploy is the easy part. Qualify for structural (not just marginal) ROI, design pilots, capture baselines, enable champions, preempt failure modes. Also on FDE.
1h 13m + 1h 10m practice Claude Code Partner Badge Structural vs marginal gain · 30-day activation

Key distinction

Marginal gainStructural gain
Same work, faster. Real, but hard to sell a CIO in 30 days.The unit of work changes. 4 people / 6 weeks → 2 developers / 2 weeks. Measurable before Day 30.

Engagement arc

  • Use case qualification — volume, complexity, measurability, developer readiness
  • Pilot design — cohort, scope, duration, Day-30 success criteria
  • ROI — baseline before Day 1 (no baseline = no denominator)
  • Phased rollout — supervised use → agentic delegation is designed, not hoped for
  • Champion enablement — CLAUDE.md + internal docs as deployment infrastructure
  • Preempt common failure modes
  • 30-day activation walkthrough — pre-kickoff, weekly CoE + office hours, Day 30 showcase, plugin/docs handoff
Artifact: Delivery Plan Pack — use case qualification, pilot design, ROI scorecard, champion plan for a sample brief.
