Building an Agentic Slackbot with Claude Code

How Hivebrite built a production incident-management Slackbot using Claude Code as a subprocess, Go for the runtime, Vertex AI for cost-effective model access, and Kubernetes for deployment — plus the architecture-first lesson that saved the most time.

What Was Built

An incident management Slackbot for on-call engineers. It surfaces past postmortems, monitors alerts, tracks vendor outages — all through natural language in Slack — while Claude Code handles the reasoning and MCP servers connect to production systems.

Incident Summarization

Searches past Confluence postmortems for similar incidents, surfaces root causes and resolution steps.

Datadog Alert Polling

Polls active Datadog alerts and posts updates to dedicated Slack incident channels.

Vendor Status Monitoring

Tracks external vendor outages automatically — no manual status page checking.

Multi-Surface

Works in channels, DMs, and via @mention. Context-aware across conversation threads.

Architecture Stack

Brain

Claude Code CLI

Invoked as a subprocess via exec.Command("claude", "-p", prompt). Handles all AI reasoning.

Runtime

Go (~2,000 lines)

Using rs/zerolog for structured logging and spf13/viper for configuration.

AI Backend

Deployment

Helm chart for deployment configuration. GCP Artifact Registry for container images.

Tools

MCP Servers

Atlassian MCP (Confluence), Datadog MCP, custom Python scripts as additional tools.

Infra

Terraform + GCP

Artifact Registry, Workload Identity. Note: Model Garden activation requires manual UI step — no Terraform support yet.

Core Pattern: Claude Code as Subprocess

The key architectural decision: invoke Claude Code CLI as a subprocess, not via SDK calls. This gives the bot full access to Claude's tool-use, MCP integration, and agent loop without implementing any of it manually. 

package agent

import (
    "context"
    "encoding/json"
    "fmt"
    "os/exec"
    "strings"
)

type ClaudeAgent struct {
    mcpServers []string
    systemPrompt string
}

// InvokeWithPrompt runs Claude Code CLI as a subprocess
func (a *ClaudeAgent) InvokeWithPrompt(ctx context.Context, userPrompt string) (string, error) {
    args := []string{"-p", a.buildFullPrompt(userPrompt)}

    // Add MCP server configurations
    for _, server := range a.mcpServers {
        args = append(args, "--mcp-config", server) // path to an MCP config JSON file
    }

    cmd := exec.CommandContext(ctx, "claude", args...)
    output, err := cmd.Output()
    if err != nil {
        return "", fmt.Errorf("claude invocation failed: %w", err)
    }
    return strings.TrimSpace(string(output)), nil
}

// Well-structured XML prompts produce consistent Claude responses
func (a *ClaudeAgent) buildFullPrompt(userQuery string) string {
    return fmt.Sprintf(`

%s




  Confluence postmortems and incident history
  Active alerts, monitors, and metrics
  External service status pages




%s



1. Search for relevant past incidents in Confluence matching the query topic
2. Check active Datadog alerts that may be related
3. Verify relevant vendor status pages
4. Synthesize findings into a concise incident summary with recommended next steps
5. Format your response for Slack (use *bold* for emphasis, bullet points for lists)

`, a.systemPrompt, userQuery)
}
Why subprocess over SDK? Claude Code CLI handles the full agent loop, MCP server connections, tool retries, and context management. Using it as a subprocess means the Go code owns routing, state, and Slack integration — Claude owns the AI reasoning. Clean separation of concerns.

Slack Integration Pattern

// JavaScript equivalent of the Slack event handler pattern
// (The actual implementation is Go — this shows the routing logic)

class SlackBot {
  constructor(claudeAgent, slackClient) {
    this.agent  = claudeAgent;
    this.slack  = slackClient;
    this.channels = new Map(); // incident channel state
  }

  // Handle incoming Slack events
  async handleEvent(event) {
    // Route based on event type and context
    if (event.type === "app_mention") {
      await this.handleMention(event);
    } else if (event.type === "message" && this.channels.has(event.channel)) {
      await this.handleIncidentChannelMessage(event);
    }
  }

  async handleMention(event) {
    const query = this.extractQuery(event.text);
    await this.slack.postTypingIndicator(event.channel);

    // Build well-structured prompt with XML structure
    const prompt = this.buildIncidentPrompt(query, {
      channel: event.channel,
      user: event.user,
      timestamp: event.ts
    });

    const response = await this.agent.invoke(prompt);

    await this.slack.postMessage({
      channel: event.channel,
      thread_ts: event.ts,
      text: response,
      // Slack Block Kit formatting for better UX
      blocks: this.formatAsBlocks(response)
    });
  }

  // Proactive alert posting — no user trigger needed
  async pollAndPostAlerts() {
    const activeAlerts = await this.agent.invoke(
      "Check Datadog for any alerts in CRITICAL or WARNING state fired in the last 15 minutes. " +
      "For each alert, include: alert name, service, severity, triggered time, and link."
    );

    if (activeAlerts.includes("No active alerts")) return;

    // Post to all registered incident channels
    for (const [channelId] of this.channels) {
      await this.slack.postMessage({
        channel: channelId,
        text: `:rotating_light: Active Alerts\n${activeAlerts}`
      });
    }
  }

  buildIncidentPrompt(query, context) {
    // XML structure produces more consistent agent responses
    return `

  ${context.channel}
  ${context.user}
  ${context.timestamp}

${query}
    `.trim();
  }

  extractQuery(text) {
    // Remove bot mention from message
    return text.replace(/<@[A-Z0-9]+>/g, "").trim();
  }

  formatAsBlocks(text) {
    return [{
      type: "section",
      text: { type: "mrkdwn", text: text.substring(0, 3000) } // Slack block text limit
    }];
  }
}

Key Engineering Lessons

  • Architecture-first saves the most time. Moving hackathon code to legacy-project/ and writing a markdown architecture document before rebuilding "saved a massive amount of time." Time spent on upfront architecture compounds positively.
  • Well-structured XML prompts produce consistent responses. Claude handles XML-structured prompts reliably. Tags like <context>, <query>, and <instructions> structure the model's reasoning visibly.
  • Vibe engineering, not vibe coding. The author could "take ownership of the resulting codebase right away" — the distinction is deliberate AI-assisted engineering vs. unreviewed generation. You review and understand what the AI produces.
  • Vertex AI for cost, direct API for simplicity. GCP Model Garden reduces token costs meaningfully at scale. The tradeoff: manual activation step, Workload Identity setup, region availability constraints.
  • MCP servers vs. custom tools. For well-supported services (Confluence, Datadog), existing MCP servers save weeks. For custom internal tools, lightweight Python scripts work well as additional tool definitions.

Key Takeaway

The pattern "Claude Code as subprocess + Go for routing and integration" cleanly separates AI reasoning from application concerns. Claude handles the agent loop, MCP connections, and tool orchestration; Go handles Slack events, state management, and operational concerns. The architecture-first lesson applies broadly: when rebuilding a hackathon prototype, the markdown design document is not documentation overhead — it's the fastest path to a maintainable codebase. For Vertex AI deployment, budget for the manual model activation step and test your Workload Identity configuration early — these are the two most common setup blockers.
