Ensuring No Personally Identifiable Information (PII) Is Leaked

Detect and redact PII on both sides of an LLM call with the analyzer and anonymizer pattern from Microsoft Presidio, including a streaming output guard.

The most expensive failures are quiet ones: PII logged by a provider you never audited.

Core idea: Defend both directions: do not send PII out, and do not let retrieved PII reach the user.

Lesson 8

Ensuring no personal identifiable information is leaked

PII means names, emails, social security numbers and similar data. The lesson sets out a two-part defence:

  • Input side — stop customer or organisation data from reaching a third-party LLM provider in the API request.
  • Output side — sanitise generated responses so retrieved internal data is not exposed to users; the lesson does this in real time on a stream.

Microsoft Presidio

  • Analyzer engine — finds entities and returns entity type, start and end positions.
  • Anonymizer engine — replaces detected spans with placeholders such as person or phone-number tags.

The custom validator registers with the framework and implements validate(). The example: a pizza-shop customer, Hank Tate, volunteers contact details. Organisations should choose between detection (block) and anonymisation (rewrite) according to their risk tolerance and regulatory duties.

Code

Analyzer, anonymizer, input guard and a streaming output guard

Regex and Luhn checksum recognisers stand in for Presidio’s analyzer. Note the order-number that is not flagged because it fails Luhn, and the streaming guard that buffers to sentence boundaries.

JavaScript Example 
// ── Mini guardrails core (mirrors the Guardrails AI vocabulary: Validator, Guard, on_fail) ──
class ValidationError extends Error {}
const pass = () => ({ outcome: 'pass' });
const fail = (errorMessage, fixValue) => ({ outcome: 'fail', errorMessage, fixValue });

class Guard {
  constructor(name = 'guard') { this.name = name; this.rules = []; this.log = []; }
  use(validator, onFail = 'exception') { this.rules.push({ validator, onFail }); return this; }
  validate(text) {
    let cur = text;
    for (const { validator, onFail } of this.rules) {
      const r = validator.validate(cur);
      this.log.push({ validator: validator.constructor.name, outcome: r.outcome, onFail });
      if (r.outcome === 'pass') continue;
      if (onFail === 'exception') throw new ValidationError(`Validation failed for ${this.name}: ${r.errorMessage}`);
      if (onFail === 'fix' && r.fixValue !== undefined) cur = r.fixValue;   // replace and continue
      else if (onFail === 'filter') return null;                              // drop the whole value
      // 'noop': record the failure, keep the value
    }
    return cur;
  }
}

// Presidio's shape: an ANALYZER finds entities {type,start,end,score}; an ANONYMIZER rewrites the text.
// Stand-in recognisers: regex + Luhn checksum + a "my name is / Mr." context rule for PERSON.
const luhn = d => { let s = 0, alt = false; for (let i = d.length - 1; i >= 0; i--) { let n = +d[i]; if (alt) { n *= 2; if (n > 9) n -= 9; } s += n; alt = !alt; } return s % 10 === 0; };
const RECOGNISERS = [
  { type: 'EMAIL_ADDRESS', re: /[\w.+-]+@[\w-]+(?:\.[\w-]+)+/g },
  { type: 'US_SSN',        re: /\b\d{3}-\d{2}-\d{4}\b/g },
  { type: 'CREDIT_CARD',   re: /\b(?:\d[ -]?){13,16}\b/g, check: m => luhn(m.replace(/\D/g, '')) },
  { type: 'PHONE_NUMBER',  re: /(?<![\d-])(?:\+?1[ -]?)?(?:\(\d{3}\)|\d{3})[ -]?\d{3}[ -]?\d{4}\b/g },
  { type: 'PERSON',        re: /(?<=\b(?:my name is|i am|i'm|this is|Mr\.|Mrs\.|Ms\.|Dr\.)\s)[A-Z][a-z]+(?:\s[A-Z][a-z]+)?/g },
];
function analyze(text) {
  const found = [];
  for (const { type, re, check } of RECOGNISERS)
    for (const m of text.matchAll(re))
      if (!check || check(m[0])) found.push({ type, start: m.index, end: m.index + m[0].length });
  found.sort((a, b) => a.start - b.start);
  return found.filter((e, i) => i === 0 || e.start >= found[i - 1].end);  // drop overlaps
}
function anonymize(text, entities) {
  let out = '', pos = 0;
  for (const e of entities) { out += text.slice(pos, e.start) + `<${e.type}>`; pos = e.end; }
  return out + text.slice(pos);
}
class DetectPII {
  constructor(entityTypes) { this.types = new Set(entityTypes); }
  validate(text) {
    const hits = analyze(text).filter(e => this.types.has(e.type));
    return hits.length
      ? fail(`PII detected: ${[...new Set(hits.map(h => h.type))].join(', ')}`, anonymize(text, hits))
      : pass();
  }
}
// Output side: stream chunks, but only release text once a full sentence is buffered and validated.
async function* guardStream(chunks, guard) {
  let buf = '';
  for await (const c of chunks) {
    buf += c;
    const parts = buf.split(/(?<=[.!?])(?<!\b(?:Mr|Mrs|Ms|Dr)\.)\s+/);   // don't split after "Mr."
    buf = parts.pop();                                   // keep the unfinished sentence buffered
    for (const sentence of parts) yield guard.validate(sentence) + ' ';
  }
  if (buf) yield guard.validate(buf);
}
//---demo---
const TYPES = ['EMAIL_ADDRESS', 'PHONE_NUMBER', 'US_SSN', 'CREDIT_CARD', 'PERSON'];
const msg = "Hi, my name is Hank Tate. Call me on 555-201-7788 or mail hank.tate@example.com. Card 4111 1111 1111 1111, order #4111 1111 1112.";

console.log('analyze :', JSON.stringify(analyze(msg).map(e => `${e.type}[${msg.slice(e.start, e.end)}]`)));
console.log('anonymize:', anonymize(msg, analyze(msg)));

// Input side: block before the text ever reaches a third-party LLM API.
const inputGuard = new Guard('input').use(new DetectPII(TYPES), 'exception');
try { inputGuard.validate(msg); } catch (e) { console.log('input   :', e.message); }

// Same detector, on_fail=fix -> sanitise instead of refusing.
console.log('fixed   :', new Guard('input-fix').use(new DetectPII(TYPES), 'fix').validate(msg));

// Output side: the LLM streams a reply that accidentally contains retrieved customer data.
async function* llmStream() { for (const c of ['Sure! Your order is on the way. ', 'The driver will call Mr. Tate', ' at 555-201-', '7788 when he arrives. ', 'Enjoy your pizza!']) yield c; }
const outputGuard = new Guard('output').use(new DetectPII(TYPES), 'fix');
let streamed = ''; for await (const piece of guardStream(llmStream(), outputGuard)) streamed += piece;
console.log('stream  :', streamed);

Senior notes

What goes wrong in practice

  • Streaming vs validation. You cannot validate a token you have not seen. Buffer to a safe boundary (sentence) and accept the latency, or validate after the fact and accept exposure. Split numbers (“555-201-” / “7788”) make chunk-level regex useless.
  • Sentence splitters break on abbreviations. This demo’s first run split after “Mr.” and missed the name; the fix is in the code. Test your splitter with your data.
  • Checksums cut false positives. A 16-digit order number is not a card number unless Luhn passes.
  • Placeholders preserve utility. Replacing with typed tags lets the LLM still reason about “a phone number was given”.
  • Regulatory view: sending PII to a third-party processor can itself be the violation (GDPR/HIPAA-style regimes), so input-side detection matters more than output-side.
  • Reversible redaction (token vault mapping tags back) is a pattern if the answer must be personalised after the LLM call.

FAQ

Frequently Asked Questions

Block or redact?

Block when any PII is a policy violation; redact when you need the rest of the message. Redaction is the friendlier default for chat.

Is regex enough?

For structured PII (email, SSN, cards) mostly yes. Names and addresses need NER or context rules, which is why Presidio combines both.

Key Takeaway

Detect with typed entities, anonymise with placeholders, validate streams at sentence boundaries, and run the input guard first.
