Hallucination Detection with Natural Language Inference

How to catch hallucinations as groundedness failures: split the answer into sentences, retrieve supporting sources, run NLI, and wrap the validator in a guard inside the chatbot.

Hallucination detection becomes tractable once you stop asking “is it true?” and ask “is it supported by what I trust?”.

Core idea: Groundedness = every output sentence is entailed by at least one trusted source.

Lesson 5

Checking for hallucinations with Natural Language Inference

The instructor notes that hallucinations have caused real consequences, including lawsuits and fines. The course narrows the problem to groundedness: you have trusted sources, and the question is whether the model’s output is faithful to them.

NLI in one paragraph

An NLI model takes a premise (trusted text) and a hypothesis (a claim) and labels the pair entailment (premise supports the claim), contradiction, or neutral (premise does not say). The course uses a fine-tuned NLI “provenance” model published under the Guardrails AI Hugging Face organisation, run through a Hugging Face pipeline.

The validator algorithm

  1. Sentence-split the LLM output (NLTK tokenizer).
  2. Retrieve relevant sources per sentence: embed sources and sentence with the same model (all-MiniLM-L6-v2), cosine similarity, take the top 5.
  3. Entailment check: sentence as hypothesis, each retrieved source as premise.
  4. Decide: a sentence is grounded if any source entails it; fail the output if any sentence is not.
  • Class shape: __init__(embedding_model, sources, entailment_model), sentence_splitter(), find_relevant_sources(), check_entailment(), validate(). All three components are held as instance state so every method can reach them.
Lesson 6

Using the hallucination guardrail in a chatbot

  • Direct use of a validator suits testing and debugging.
  • Wrapping in a Guard adds: combining multiple guardrails, streaming support, OpenAI-compatible endpoints, centralised logging and error handling.
  • Grounded is not the same as true. “The sun rises in the east” passes against the sources; “The sun is a star” fails even though it is factually true, because the sources do not contain it. That is the intended behaviour for a company chatbot.
  • Integration: swap the OpenAI client for one pointed at the guard server; catch the validation exception and implement graceful handling.
Code

Groundedness guard: split, retrieve, entail

Stand-ins: hashed bag-of-words for embeddings and a lexical entailment rule for NLI. The pipeline, the top-k retrieval and the guard wrapper are the real structure.

JavaScript Example 
// ── Mini guardrails core (mirrors the Guardrails AI vocabulary: Validator, Guard, on_fail) ──
class ValidationError extends Error {}
const pass = () => ({ outcome: 'pass' });
const fail = (errorMessage, fixValue) => ({ outcome: 'fail', errorMessage, fixValue });

class Guard {
  constructor(name = 'guard') { this.name = name; this.rules = []; this.log = []; }
  use(validator, onFail = 'exception') { this.rules.push({ validator, onFail }); return this; }
  validate(text) {
    let cur = text;
    for (const { validator, onFail } of this.rules) {
      const r = validator.validate(cur);
      this.log.push({ validator: validator.constructor.name, outcome: r.outcome, onFail });
      if (r.outcome === 'pass') continue;
      if (onFail === 'exception') throw new ValidationError(`Validation failed for ${this.name}: ${r.errorMessage}`);
      if (onFail === 'fix' && r.fixValue !== undefined) cur = r.fixValue;   // replace and continue
      else if (onFail === 'filter') return null;                              // drop the whole value
      // 'noop': record the failure, keep the value
    }
    return cur;
  }
}

// Hallucination = "not grounded in sources I trust". Pipeline from the lesson:
//   split output into sentences -> retrieve top-k relevant sources per sentence (embeddings + cosine)
//   -> NLI(premise=source, hypothesis=sentence) -> fail if any sentence is not entailed.
// Stand-ins: hashed bag-of-words "embedding" and a lexical NLI, so this runs with zero downloads.
// In the course these are all-MiniLM-L6-v2 and a fine-tuned NLI "provenance" model.
const STOP = new Set('a an the is are was were of in on at to and or for it its this that with by be as from'.split(' '));
const NEG = new Set(['not', 'no', 'never', 'cannot', "isn't", "doesn't", "don't"]);
const toks = s => (s.toLowerCase().match(/[a-z']+/g) || []);
const content = s => toks(s).filter(w => !STOP.has(w) && !NEG.has(w)).map(w => w.replace(/(es|s)$/, ''));

function embed(text, dim = 64) {                         // hashed bag-of-words, L2-normalised
  const v = new Float64Array(dim);
  for (const w of content(text)) { let h = 0; for (const c of w) h = (h * 31 + c.charCodeAt(0)) >>> 0; v[h % dim] += 1; }
  const n = Math.hypot(...v) || 1; return v.map(x => x / n);
}
const cosine = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0);

function nli(premise, hypothesis) {                      // -> 'entailment' | 'contradiction' | 'neutral'
  const p = new Set(content(premise)), h = content(hypothesis);
  const covered = h.filter(w => p.has(w)).length / (h.length || 1);
  const negP = toks(premise).some(w => NEG.has(w)), negH = toks(hypothesis).some(w => NEG.has(w));
  if (covered >= 0.8 && negP !== negH) return 'contradiction';
  return covered >= 0.8 ? 'entailment' : 'neutral';
}

class HallucinationValidator {
  constructor(sources, { topK = 5, embedFn = embed, nliFn = nli } = {}) {
    this.sources = sources; this.topK = topK; this.embedFn = embedFn; this.nliFn = nliFn;
    this.sourceVecs = sources.map(s => embedFn(s));      // pre-compute once, not per request
  }
  sentenceSplitter(text) { return text.split(/(?<=[.!?])\s+/).filter(Boolean); }
  findRelevantSources(sentence) {
    const q = this.embedFn(sentence);
    return this.sources.map((s, i) => ({ s, sim: cosine(q, this.sourceVecs[i]) }))
      .sort((a, b) => b.sim - a.sim).slice(0, this.topK).map(x => x.s);
  }
  checkEntailment(premise, hypothesis) { return this.nliFn(premise, hypothesis) === 'entailment'; }
  validate(text) {
    const hallucinated = this.sentenceSplitter(text).filter(sent =>
      !this.findRelevantSources(sent).some(src => this.checkEntailment(src, sent)));
    return hallucinated.length ? fail(`Hallucinated content: ${JSON.stringify(hallucinated)}`) : pass();
  }
}
//---demo---
const SOURCES = [
  'The sun rises in the east.',
  "Alfredo's Pizza Cafe opens at 11am daily.",
  'Delivery is free for orders over 25 USD.',
];
const v = new HallucinationValidator(SOURCES);
// 1) Using the validator directly: good for tests and debugging.
for (const t of ['The sun rises in the east.', 'The sun is a star.', 'The sun never rises in the east.'])
  console.log(`direct  | ${v.validate(t).outcome.padEnd(4)} | ${t}`);

// 2) Wrapped in a Guard: combine validators, choose on_fail, collect a log.
const outputGuard = new Guard('output').use(v, 'exception');
const llm = q => /open/.test(q) ? "Alfredo's Pizza Cafe opens at 11am daily." : 'Our Veggie Supreme has bell peppers. It bakes for 12 minutes.';
for (const q of ['When do you open?', 'Tell me about the Veggie Supreme']) {
  try { console.log('guarded |', outputGuard.validate(llm(q))); }
  catch (e) { console.log('guarded |', e.message.slice(0, 110)); }
}
console.log('log     |', JSON.stringify(outputGuard.log));

Senior notes

Failure modes and scaling

  • Pre-compute source embeddings in the constructor; recomputing per request is the first latency bug.
  • Sentence granularity cuts both ways. Claims spanning two sentences (“It opens at 11. That is when it closes.”) lose their referent; coreference needs context windows or paragraph-level checks.
  • Top-k is a recall knob. Too small and a supported claim looks unsupported; too large and NLI cost rises linearly per sentence.
  • NLI inputs are length-limited (typically a few hundred tokens), so long sources must be chunked.
  • Decide what a false positive costs. Strict groundedness blocks harmless small talk; pair with on_fail=fix or a canned fallback for those cases.
  • Where this is used: RAG for support, legal and finance assistants, where “only say what the sources say” is a contractual requirement.

FAQ

Frequently Asked Questions

Why use NLI instead of asking another LLM “is this true?”

An NLI model is small, consistent, private and cheap to run per sentence. An LLM judge is stochastic, rate-limited and sends data to a third party.

Does passing mean the answer is correct?

No. It means the answer is supported by your sources. If the sources are wrong, a grounded answer is wrong.

Key Takeaway

Check claims against your sources sentence by sentence; treat grounded as the goal and factual as out of scope.
