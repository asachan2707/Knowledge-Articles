Preventing Competitor Mentions

Stop a chatbot from naming rivals with a cascade of exact matching, named-entity recognition and embedding similarity, including the own-brand collision trap.

Source: DeepLearning.AI × GuardrailsAI (L9) Instructor: Shreya Rajpal (GuardrailsAI) · Domain: AI Safety · Guardrails
PAGE SUMMARY (hidden, for analysis). Child 06. Covers L9 Preventing competitor mentions (Pizza by Alfredo). Cascade: exact regex, BERT NER, sentence-transformer cosine with threshold. Runnable JS cascade with own-brand exclusion.

Brand-safety rules are cheap to state and easy to violate; cascades make them cheap to enforce.

Core idea: Run the cheapest detector first, add progressively fuzzier ones, short-circuit on the first hit.

Lesson 9

Preventing competitor mentions

The Alfredo’s Pizza chatbot is first shown reproducing the failure: asked to compare itself with “Pizza by Alfredo”, it names the rival and makes claims. The goal is to prevent any direct mention of rival businesses.

Cascading detection (cheap first)

  1. Exact match against known competitor names, lower-cased, with regex.
  2. NER: a BERT-based model extracts organisation entities (filtering tags that mark entity boundaries and classes: person, organisation, location).
  3. Vector similarity: sentence-transformer embeddings of extracted entities vs pre-computed competitor embeddings, cosine similarity (scikit-learn) against a threshold.

If the exact match hits, validation fails immediately; otherwise entities above the similarity threshold fail with the list of detected competitors; if nothing matches, it passes. The guarded client then detects “Pizza by Alfredo” and blocks the reply.

Code

Exact → entity → similarity cascade

Capitalised-phrase extraction stands in for the BERT NER model and character-trigram vectors for sentence-transformer embeddings. Misspellings (“Dominos”, “Papa John”) are caught by the similarity stage.

JavaScript Example 
// ── Mini guardrails core (mirrors the Guardrails AI vocabulary: Validator, Guard, on_fail) ──
class ValidationError extends Error {}
const pass = () => ({ outcome: 'pass' });
const fail = (errorMessage, fixValue) => ({ outcome: 'fail', errorMessage, fixValue });

class Guard {
  constructor(name = 'guard') { this.name = name; this.rules = []; this.log = []; }
  use(validator, onFail = 'exception') { this.rules.push({ validator, onFail }); return this; }
  validate(text) {
    let cur = text;
    for (const { validator, onFail } of this.rules) {
      const r = validator.validate(cur);
      this.log.push({ validator: validator.constructor.name, outcome: r.outcome, onFail });
      if (r.outcome === 'pass') continue;
      if (onFail === 'exception') throw new ValidationError(`Validation failed for ${this.name}: ${r.errorMessage}`);
      if (onFail === 'fix' && r.fixValue !== undefined) cur = r.fixValue;   // replace and continue
      else if (onFail === 'filter') return null;                              // drop the whole value
      // 'noop': record the failure, keep the value
    }
    return cur;
  }
}

// Cascade, cheapest first: (1) exact match  (2) entity extraction  (3) embedding similarity.
// Stand-ins: capitalised-phrase "NER" (the course uses a BERT NER model) and character-trigram vectors
// (the course uses sentence-transformers). Structure and thresholds work the same way.
const trigrams = s => { const t = ` ${s.toLowerCase().replace(/[^a-z ]/g, '')} `; const m = new Map(); for (let i = 0; i < t.length - 2; i++) m.set(t.slice(i, i + 3), (m.get(t.slice(i, i + 3)) || 0) + 1); return m; };
const cos = (a, b) => { let d = 0, na = 0, nb = 0; for (const [k, v] of a) { na += v * v; d += v * (b.get(k) || 0); } for (const v of b.values()) nb += v * v; return d / Math.sqrt(na * nb || 1); };

function extractOrgs(text) {                                  // "Pizza by Alfredo", "Domino's", "Papa Johns"
  const re = /\b[A-Z][\w']*(?:\s(?:by|of|&|and)?\s?[A-Z][\w']*)*/g;
  return [...text.matchAll(re)].map(m => m[0]).filter(s => s.includes(' ') || /'s$|s$/.test(s));
}
class CompetitorCheck {
  constructor(competitors, { threshold = 0.6, ownBrands = [] } = {}) {
    this.competitors = competitors; this.threshold = threshold; this.ownBrands = ownBrands;
    this.vecs = competitors.map(c => trigrams(c));            // pre-computed once
  }
  exactMatch(text) { return this.competitors.filter(c => new RegExp(`\\b${c.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')}\\b`, 'i').test(text)); }
  fuzzyMatch(text) {
    const hits = new Set();
    for (const ent of extractOrgs(text)) { const v = trigrams(ent);
      this.vecs.forEach((cv, i) => { if (cos(v, cv) >= this.threshold) hits.add(this.competitors[i]); }); }
    return [...hits];
  }
  validate(raw) {
    // Our own brand is lexically close to a competitor ("Alfredo's Pizza Cafe" vs "Pizza by Alfredo"): remove it first.
    const text = this.ownBrands.reduce((t, b) => t.split(b).join(' '), raw);
    const exact = this.exactMatch(text);
    if (exact.length) return fail(`Competitor mentioned (exact): ${exact.join(', ')}`);
    const fuzzy = this.fuzzyMatch(text);
    return fuzzy.length ? fail(`Competitor mentioned (similar): ${fuzzy.join(', ')}`) : pass();
  }
}
//---demo---
const check = new CompetitorCheck(['Pizza by Alfredo', "Domino's", 'Papa Johns'], { ownBrands: ["Alfredo's Pizza Cafe"] });
const guard = new Guard('competitors').use(check, 'exception');
for (const t of [
  "Alfredo's Pizza Cafe is far better than Pizza by Alfredo.",
  'Honestly, Dominos has soggier crusts than we do.',
  'Try Papa John for cheaper deals.',
  "Our Margherita uses fresh basil from Alfredo's Pizza Cafe farms.",
]) {
  try { guard.validate(t); console.log('ALLOW |', t); } catch (e) { console.log('BLOCK |', t, '\n        ->', e.message.replace('Validation failed for competitors: ', '')); }
}

Senior notes

Edge cases

  • Your own brand can collide with a competitor’s. “Alfredo’s Pizza Cafe” vs “Pizza by Alfredo” scored as similar in the first run of this demo, blocking legitimate text. The fix: strip own-brand names before checking, or maintain an allow list.
  • Threshold trade-off. Lower catches typos and abbreviations but flags generic words; start strict and use noop logging.
  • Competitor lists rot. Keep them in config or a database, not code, and re-embed on change.
  • Cost ordering matters: exact match is microseconds, embedding is milliseconds, NER a model call. The cascade runs the cheap tier first and short-circuits.
  • Beyond names: products, nicknames and URLs are competitor references too.

FAQ

Frequently Asked Questions

Why not just ask the LLM to avoid competitors?

That is what failed in lesson 2. The check must be outside the model.

Is blocking the whole answer too harsh?

You can use on_fail=fix to redact the mention, or regenerate with a stricter instruction.

Key Takeaway

Combine exact, entity and similarity checks in a cascade, exclude your own brand, and keep the competitor list as data.
